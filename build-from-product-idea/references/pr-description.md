# PR Description Contract

## Summary

State the approved problem and the reviewable outcome in concise terms.

## Product brief

Include the approved product brief. Link to a committed repository-native brief only when that repository already has a convention for such artifacts.

## Approved implementation plan

Include the approved implementation plan. Link to a committed repository-native plan only when that repository already has a convention for such artifacts.

## Approval checkpoint

Record that direct approval of the final brief and final plan occurred in the current session. After a material change, record fresh direct approval in the current session of both the updated final product brief and updated final implementation plan before implementation continued. Do not fabricate a quotation or timestamp.

## Actual changes

List the implementation delivered, tied to the approved scope and acceptance criteria.

## Minor deviations

List only non-material deviations and their rationale. Write `None` when there are no minor deviations. A material deviation requires updated artifacts and fresh approval before implementation continues.

## Verification evidence

Record each applicable exact command or equivalent check, its result, and the acceptance criteria it supports. Include any required manual or environment-specific evidence.

## Residual risks

State remaining known risks, limitations, and follow-up work, or write `None`.

## Remote verification

Confirm the remote repository, PR number, base branch, head branch, head SHA, non-draft state, title, and description. Include the canonical PR URL. This confirmation must come from the remote service after creation; a successful creation command is not sufficient.
